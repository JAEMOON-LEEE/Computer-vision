# 영상·사진 수동 검증 대시보드

실제 차량·보행자 확인은 **실제 영상 범용 모델 · 트럭·버스 포함**이 기본이며 **실제 CCTV 보강 모델 · 추가 학습**도 비교할 수 있다. 사람·승용차·트럭·버스·오토바이·자전거 여섯 종류를 지원하며 포트홀·낙하물·구조물은 기존 가상환경 모델에서 확인한다. 실제 사고 장면 후보 분류는 별도의 검증 기준을 통과한 경우에만 선택할 수 있고 접촉 순간·충돌 참여 차량을 확정하는 기능은 아니다. 실제 데이터 출처·학습·평가·한계는 [실제 CCTV 보강](real_traffic_training.md)에 기록한다.

## 이 방식으로 확인할 수 있는 것

미리 녹화된 실제 CCTV나 사고 영상을 재생해 모델이 어떤 객체를 잡고 어떤 경고를 내는지 확인하는 것은 타당한 사례 검사다. 실제 사고가 나기를 기다릴 필요가 없다. 다만 사용자가 사고 장면을 골라 모델을 켠 결과는 실제 CCTV의 전체 정확도·사고 재현율이 아니다.

- 사진 한 장: 차량·보행자·포트홀·낙하물·구조물의 **객체 검출**을 확인한다. 사진에서 차량과 구조물이 겹쳤다고 추돌을 판정하지 않는다.
- 연속 영상: 사고 전 접근, 접촉, 이후 멈춤을 포함한다. 사고보다 최소3초 앞에서 켜는 것을 권장한다. 현재 경고는 고정 카메라에서 관측한 움직임·겹침·급정지에 기반한 **의심 경고**다.
- 화면 공유: 캡처 경과 시각을 사용하므로 원본 영상의 재생 시각·배속·편집을 완전히 검증할 수 없다. 사례 확인용으로 쓰고 정량 성능 평가와 구분한다. 공유한 재생 화면을 일시정지·탐색·전환하면 OFF→ON으로 이력을 새로 시작한다.
- 정량 평가: 재현 가능한 파일, 사고 전후 구간과 실제 정답 시각·박스, 사고 없는 대조 구간을 별도로 마련한다. 같은 카메라·같은 사건에서 나온 잘린 영상을 train/test에 나눠 넣지 않는다. 모델과 임계값을 고정한 독립 평가 자료를 사용한다.

유튜브의 편집·자막·줌·움직이는 카메라·뉴스 합성 화면은 CCTV 환경과 다를 수 있다. 검출 신뢰도는 정답 확률이나 시스템 정확도를 뜻하지 않는다. 원하는 장면만 골라 반복 조정한 뒤 같은 장면을 시험 성능으로 발표하지 않는다.

현재 모델의 `barrier`는 학습한 도로 구조물 범주다. 임의의 건물 붕괴·크레인·큰 구조물 낙하를 전부 인식하는 모델이 아니다. `debris` 검출도 낙하 **동작** 인식을 뜻하지 않는다. 야간 사고 누락·조기경고와 실제 CCTV 자막 오탐은 남아 있다.

## 유튜브와 입력 방식

주소를 입력하면 공식 YouTube iframe으로 참고 영상을 재생한다. 공식 API는 재생·정지·시각 조회를 제공하지만 원시 프레임 입력을 제공하는 API는 아니다. 다른 출처 iframe의 픽셀을 직접 읽어 오는 연결로 구현하지 않았다. YouTube 콘텐츠의 자동 다운로드·저장·플레이어 변경에는 공식 정책상 제한이 있다.

모델 입력은 사용자가 직접 연결한 화면 또는 브라우저에서 선택한 영상·사진이다. 화면 연결은 `getDisplayMedia`의 브라우저 선택창에서 사용자가 탭·창을 직접 고르고 권한을 부여해야 한다. 재생 중인 참고 영상을 확인할 때에는 분석 권한이 있는 자료를 사용하고, 실제 영상 부분을 분석 영역으로 지정한다. 플레이어의 컨트롤·광고·표시를 변경하거나 우회하지 않는다. 화면 연결을 종료하면 모델도 꺼진다. 권한을 계속 재사용하도록 자동 승인하거나 녹화 원본을 자동으로 내려받는 기능은 없다.

화면 공유가 지원되지 않는 브라우저, 보호된 콘텐츠의 검은 화면, 재생 허용이 꺼진 iframe은 우회하지 않는다. 그 경우 사용 권한이 있는 원본 영상·사진 파일을 입력한다.

참고: [YouTube iframe API](https://developers.google.com/youtube/iframe_api_reference), [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [브라우저 화면 공유](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia).

## 실행

프로젝트 루트에서 `validation_lab.bat`을 실행하거나 PowerShell에서 `./start_validation_lab.ps1`을 실행한다.
BAT 실행은 서버 준비를 확인한 뒤 기본 브라우저를 연다. 서버를 종료하려면 `./stop_validation_lab.ps1`을 실행한다. 결과 파일은 지우지 않는다.

- 화면: `http://127.0.0.1:5174/lab`
- API: `http://127.0.0.1:8001`
- 결과·로그: `D:\Capston disign\Computer-vision\runs\validation-lab`

실행기는 창을 숨겨 두 프로세스를 시작하고 포트가 이미 사용 중이면 확인한다. 같은 검증 서버가 실행 중이면 기존 주소를 반환한다. 기존 팀 대시보드 화면·검출기·경고 엔진을 재사용한다. 기존 관제의 DB는 이번 실행에서 D드라이브의 별도 SQLite로 지정하며 팀 Supabase DB와 연결하지 않는다. 학습·가중치 수정이나 자동 GitHub 업로드는 하지 않는다.

설치가 필요한 새 PC에서는 프로젝트의 `.venv`에 `backend/requirements.txt`와 `detection/requirements-cpu.txt`를 설치하고, `frontend`에서 잠금 파일에 맞춰 `npm ci`를 실행한다. TEMP/TMP와 pip/npm/YOLO/Torch/HF 캐시는 D 경로를 먼저 지정한다. 모델은 Git LFS의 실제 파일이 있어야 한다.

## 사용 순서

1. 유튜브 주소를 넣어 참고 재생하거나, 영상·사진 파일을 고른다. 화면을 분석할 때는 **화면 연결**에서 재생 탭·창을 선택한다. 대시보드 자체를 공유하면 반복 화면이 생기므로 실제 재생 창을 고른다.
2. 필요하면 **분석 영역 설정**으로 자막·화면 테두리를 제외한다. 새 입력을 고르면 영역과 고정 카메라 선택을 초기화한다. 이 영역은 사용자가 지정한 범위이며 자동 도로 분할 결과가 아니다.
3. 충돌 보강 주간·야간, 이전 주간·야간, 이전 주간 비교 모델을 선택한다. 새 모델은 학습·시험 완료 후 활성화된다. 사진은 **현재 한 장만 검사**로 본다. 영상은 **모델 켜기/끄기**로 원하는 시점을 검사한다.
4. 충돌 의심 경고는 **고정 카메라 영상**을 선택하고 초당5장 또는8장을 사용할 때 표시한다. 초당2장은 객체 확인용이다. 카메라가 이동하는 블랙박스·편집 영상에는 이 충돌 규칙의 유효성을 주장하지 않는다.

가상환경의 새 재학습 판정을 사용할 때는 **충돌 보강 주간·야간 모델**과 **가상 CCTV 전용 충돌 판정 사용**을 함께 선택한다. 이 판정은 실제 CCTV에 자동 적용하지 않는다. 이전 모델과 새 모델·판정의 학습 및 비교 결과는 [주간·야간 충돌 재학습](collision_retraining.md)에 있다.
5. 영상 파일은 **정밀 구간 검사**가 기본이다. 현재 위치 또는 입력한 시작·끝 사이를 원본 시각에 맞춰 한 장씩 처리한다. CPU가 느려도 시간 순서를 건너뛰지 않는다. 끝에 도달하면 OFF된다. 이 모드에서 수동 재생·탐색을 하면 분석을 중단한다. 실시간 따라가기는 컴퓨터가 느릴 때 프레임을 놓칠 수 있다.
6. **현재 한 장만 검사**는 영상에서도 충돌 경고 없이 객체 검출만 하고 자동 OFF한다. 켜기·끄기를 반복하거나 새 구간을 시작하면 추적 이력을 재사용하지 않는다. OFF 이전에 이미 처리 중이던 요청의 결과는 화면에 뒤늦게 적용하지 않는다.
7. 실제 검출 여부를 직접 판정하고 **결과를 D드라이브에 저장**한다. 세션마다 `session.json`, `events.jsonl`, `detections.jsonl`, `alerts.jsonl`(경고가 있을 때), `report-*.json`이 남는다. 원본 프레임·영상은 서버에 저장하지 않는다. 결과는 원본 영상과 같은 시각의 정지 프레임에 표시하며 재생 중인 다른 시각 위에 박스를 씌우지 않는다.

실제 CCTV에는 Unity 전용 원거리 ROI·정지선·대기 구역을 자동 적용하지 않는다. 이번 페이지의 충돌 경고는 기존 일반 영상 규칙을 사용하며 Unity 대기 구역 전용 RTrees를 실제 도로에 검증 없이 적용하지 않는다.

## 구현 검증 범위

2026-10-25 기준 기존 API를 포함한 백엔드48개 검사와 TypeScript/프로덕션 빌드를 통과했다. 실제 모델 사진 입력, 보관된 실제 야간 CCTV를 재인코딩한6초 UI 시험 영상에서0~0.8초 5프레임의 원본 시각 처리·자동 OFF·수동 판정·D 저장을 확인했다. 화면 입력 연결은 브라우저의 테스트 스트림으로 확인했으며 수동 OFF 후 결과 갱신 중단과 화면 연결 해제도 검사했다. 테스트 스트림은 실제 공유 권한 선택창 검사를 대신하지 않는다.

이 UI 시험 영상은 사고 정답이 있는 성능 평가 자료가 아니다. 하단 자막의 차량 오탐도 육안으로 확인했다. 특정 유튜브 사고 영상은 아직 사용자가 제공하지 않았으므로 실제 낙하·사고 사례의 인식 성공을 확인했다고 주장하지 않는다. 네이티브 화면 공유 선택과 실제 유튜브 영상 재생은 브라우저 환경·사용자 권한에 따라 직접 확인해야 한다. 검사 요약은 [QA 기록](validation/manual-lab-20261025/qa.json)에 있다.
