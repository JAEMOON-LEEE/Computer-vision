# 도로 위험 중심 전환: 현재 상태와 남은 작업

2026-11-11 작업 기록. 이 문서는 구현과 검증을 구분한다. 새로운 모델 학습, 실제 CCTV 평가, DB 변경, GitHub 업로드는 수행하지 않았다.

## 이번 변경

- `SyntheticTrainingCapture`와 `ScenarioDatasetCapture`의 신규 수집 선택지는 정상, 포트홀, 낙하물이다. 차량·구조물 충돌을 이 두 경로에서 선택하지 않는다. 기존 충돌 전용 수집기, 수동 시나리오, 모델, 데이터 및 결과는 유지한다. 기존 충돌 전용 명령을 호출하거나 과거 데이터를 직접 학습하는 것을 전역적으로 차단한 것은 아니다.
- 포트홀은 기존 소형·넓은형·길쭉한형·두 개 묶음, 낙하물은 소형·대형 블록·납작한 판·두 블록을 사용한다. 각 생성은 지정된 시드의 난수로 도로 X 위치와 두 차선 중 하나를 고른다. 수집기는 주야간 설정에 따른 조명과 기존 차량·보행자 배치를 사용한다. 가림 정도나 파손 정도를 제어하는 기능은 없다. 포트홀은 도로를 실제로 파낸 지오메트리가 아니다.
- `scenario` 정답에 기존 seed, episode, scenario, scenario_variant와 함께 `hazard_state`를 추가했다. 정상/포트홀/낙하물은 각각 normal/abnormal이고 다른 기존 장면은 not_applicable이다. 객체 박스는 기존 정답 형식을 유지한다. 시드와 동일한 호출 순서는 생성 설정을 재현하기 위한 조건이며 물리·렌더링의 비트 단위 재현은 검증하지 않았다.
- CLI `prepare-unity`는 기본 클래스 pothole,debris와 엄격 감사를 사용한다. 예: `..\tools\Run-ProjectPython.ps1 -m detection prepare-unity --train <세션경로> --val <세션경로> --test <세션경로> --out <빈출력경로>`. 경로는 실제 세션으로 교체한다. 입력 전 프레임의 시드·에피소드·상황을 요구하고 충돌 등 미지원 장면, 분할 간 동일 시드·동일 이미지 SHA-256을 거부한다. 같은 시드의 에피소드도 한 분할에 묶인다. 감사 결과는 provenance.json에 기록된다. 옛 형식 변환은 `--legacy-no-hazard-audit`로 명시적으로 선택해야 하며 새 위험 학습용 승인으로 간주하지 않는다. 직접 Python API의 기존 기본 동작은 호환성을 위해 유지하므로 `hazard_audit=True`가 필요하다.
- 정확히 같은 바이트와 기록된 시드만 검사한다. 메타데이터가 틀리거나 동일 장면을 다른 시드로 재생성한 경우, 재인코딩·근접 중복, 에셋·카메라 공유는 이 검사로 배제되지 않는다. 시드 분리는 실제 CCTV나 새 카메라 일반화의 증거가 아니다. 수집 결과에 대해 사람의 라벨 및 가림 검수가 필요하다.

## 연결 및 미완료

기존 taxonomy의 pothole/debris, YOLO 박스 변환, 검출·평가와 대시보드의 도로 파임/낙하물 표시는 재사용 가능하다. 기존 모델의 지원 클래스는 모델별로 다르며 실제 영상 범용 차량 모델은 이 위험물들을 지원하지 않는다. 새 데이터 수집이나 학습, 검증은 하지 않았고 새 변형의 성능은 알 수 없다. 기존 학습 명령은 임의 데이터셋을 여전히 받을 수 있으므로 새 학습 전에 감사된 provenance와 내용 검토가 필요하다.

시선유도봉·가드레일·신호등 상황 생성 코드와 기준 정답을 이후 추가했다. 다만 Unity 컴파일·Play 검증 및 시설물 상태 모델·평가·대시보드 연동은 **미완료**다. 세부 사항은 `facility_scenarios.md` 참조. 기존 barrier는 일반 구조물 객체로 시설물의 정상/파손 상태를 뜻하지 않으며, 누락은 객체 박스가 없는 것만으로 정답을 표현할 수 없다. 기존 팀원의 추적, 도로 인식·매핑과 백엔드·대시보드를 재사용하고 이를 중복 구현하지 않는다.

후속 설계는 카메라별 검토된 기준 위치·시설물 ID·관측 가능 영역과 버전을 기록하고, 현재 프레임과 기준을 정합한 뒤 가림/관측 불가를 별도 상태로 유지해야 한다. 가림 해소 후 여러 관측에서만 변형·누락 의심을 제시하고, 카메라 이동·장면 변경 시 비교를 중지해야 한다. 신호등은 방향과 등화 영역, 정상 주기와 점멸 이력을 고려하여 전환 유예·장시간 관측·관측 불가 상태를 두고 영상 결과를 '지속 소등 의심'으로만 제시해야 한다. 시간 임계값은 실제 자료로 정해야 하며 이 문단은 구현이나 검증 결과가 아니다.

## 확인

- `python -m unittest discover -s detection/tests`: 58개 통과. 새 감사 테스트는 시드 중복·동일 바이트·차량 충돌 거부를 포함한다. 임시 테스트 데이터이며 실제 새 데이터셋 분할 감사가 아니다.
- Unity CLI에서 설치된 6000.6.6f1 경로를 지정해 batch Editor를 열었지만 45초 준비 시간 초과(`OPEN_READY_TIMEOUT`, `noServer`), 이후 status도 인스턴스를 찾지 못했다. 프로젝트 Editor.log에는 라이선스 초기화 전 단계가 기록되어 있으며 컴파일 완료 증거가 없다. CLI 업데이트 확인도 DNS 오류로 실패했다. Unity 컴파일과 Play 검증은 미완료다. Unity 버그 보고는 전송하지 않았다.
