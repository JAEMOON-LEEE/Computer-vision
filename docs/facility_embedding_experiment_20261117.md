# 시설물 임베딩 실험

## 모델과 방법

기존 `detection/models/yolo11n.pt`의 체크포인트는 80개 클래스와 COCO 학습 설정을 담고 있다. 이 사전 학습 YOLO11n의 0~6번 층을 고정한 영상 특징 추출기로 재사용했다. 기준 ROI를 RGB 128×128, 0~1로 변환하고 특징 지도를 4×4 평균 풀링해 2,048차원 임베딩을 만들었다. YOLO 가중치는 학습하거나 변경하지 않았다. 가드레일과 맨홀에 대해 각각 임베딩을 입력받는 OpenCV RTrees 분류기를 정상·이상 훈련 프레임으로 새로 학습했다. YOLO 객체 검출 결과를 사용하거나 새 YOLO 검출 모델을 학습한 것은 아니다. 드롭아웃은 사용하지 않았다.

기존 세 데이터 묶음의 train/val/test, 2·6·12·18·22 프레임, 차량 박스와 기준 ROI의 3% 초과 겹침 제외 규칙을 직전 실험과 같게 유지했다. 두 모델이 실제로 동일한 시험 세션·프레임·정답·ROI를 사용했는지 이전 예측 파일과 자동 대조했다. 세 데이터 묶음을 합친 480세션/11,520프레임의 세션·시드·정확한 이미지 분할 중복 검사는 앞선 실험에서 통과했다.

가드레일 학습은 68세션(정상 33, 이상 35), 329프레임이며 맨홀은 55세션(정상 25, 이상 30), 275프레임이다. RTrees 설정은 직전 모델과 동일한 깊이 8, 최소 샘플 2, 나무 128개다. 임베딩 모델의 임계값은 validation F1을 최대화해 골랐고 이전 모델은 이전 validation 임계값을 유지했다. 가드레일은 이전 0.45, 임베딩 0.40이고 맨홀은 이전 0.45, 임베딩 0.50이다. 따라서 가중치뿐 아니라 각각의 임계값이 함께 다른 비교다.

## 동일 시험 결과

| 대상 | 정상 오탐: 기존 → 임베딩 | 이상 누락: 기존 → 임베딩 | 상태 분류 AP: 기존 → 임베딩 |
|---|---:|---:|---:|
| 가드레일 | 23/30 → 30/30 | 5/35 → 0/35 | 0.668 → 0.764 |
| 맨홀 | 23/25 → 20/25 | 0/30 → 0/30 | 0.863 → 0.783 |

AP는 이 실험의 세션 상태 분류 점수에 대한 101점 보간치이지 객체 검출 AP가 아니다. 가드레일 임베딩 모델은 validation 정상도 30개 전부 오경고했다. F1로 선택된 임계값에서는 시험 이상을 다 찾았지만 정상 오경고가 더 늘었다. 맨홀은 오경고가 3건 줄었지만 25개 중 20개로 여전히 높고 AP도 낮아졌다. 두 모델을 운영 가능한 개선으로 볼 수 없다.

시험 중 차량 통과 가드레일 10세션과 맨홀 5세션은 겹침 기준으로 전부 제외됐다. 겹침은 2차원 대리 지표이므로 실제 가시성을 판정하지 못한다. 시험 세트는 여러 번 확인한 소수 합성 자료이며 같은 Unity 도시·에셋과 유사한 시야를 사용하고 근접 중복도 존재한다. 실제 CCTV, 새로운 카메라 또는 독립 현장에 대한 성능은 미검증이다. 실험 추론도 합성 정답에서 얻은 기준 ROI를 사용했으며 실제 사용에는 사용자가 등록한 ROI와 별도의 가시성 판단이 필요하다. `production_ready=false`다.

## 산출물과 확인

가중치 원본 경로와 SHA-256 및 모든 결과는 `runs/facility-embedding-20261117/training/results.json`, 각 시험 세션별 예측과 제외 사례는 같은 폴더의 `*-predictions.json`, `excluded.json`에 기록했다. 새 RTrees 헤드도 같은 폴더에 있고, 특징 추출은 기존 `detection/models/yolo11n.pt`가 필요하다. 학습 코드는 `runs/facility-embedding-20261117/experiment.py`다. 저장된 가중치와 헤드를 다시 불러와 두 종류에서 각각 시험 세션 한 개의 점수를 재현했고, Python detection 테스트 64개가 통과했다. DB·GitHub·기존 모델은 변경하지 않았다.
